# Synthetic corpus universes

A **universe** is a self-contained synthetic corpus that the synthetic providers and demo gateway can load on demand: a persona cast, a per-source set of fixture files, a list of seed sources, and (optionally) a directory of replay-agent scenarios. Different universes serve different purposes — a small universe for fast E2E tests, a rich universe for product demos, a stress universe for load testing.

Everything below describes the universes under `evals/universes/`, which is the only tree `npm run validate-universes` walks. `packages/watch/universes/` borrows the word for the same idea — a self-contained fixture world a package is proven against — but nothing else: it has its own layout, its own loader, and no manifest. The two never meet.

## In-tree universes

Used by the demo gateway and as the default for E2E tests when `OMNESIS_SYNTH_UNIVERSE` is unset.                                                                                                                                    |
| `e2e-minimal`          | same seed list                                 | A slimmed-down corpus (a few entries per unstructured source, shrunk procedural configs for structured sources, no replay scenarios) for fast end-to-end tests. | `loops-test-life`      | Google mail/cal/drive/contacts                 | An ambient email + calendar corpus, every fixture dated far enough in the past that the initial sync counts as backfill. A partial universe (like the WhatsApp ones) only ships the source it cares about — the harness skips any other synth source whose fixture the universe doesn't carry.

The mechanism is universe-agnostic; pick a use case, write a new universe directory, and point the demo gateway or E2E harness at it.

## On-disk layout

```
evals/universes/<name>/
  universe.json                          # manifest
  cast.json                              # persona cast
  sources/<descriptorId>/<file>.json     # per-source fixtures
  agent-demos/                           # optional — replay-agent scenarios
    <name>.jsonl                         # one scenario
    <name>.meta.json                     # role + routing triggers + placeholders
    privacy-requests.json                # optional — external requests to drive
    _build/                              # optional — scripts that generate scenarios
```

A universe is loaded by:

- **Name** — `OMNESIS_SYNTH_UNIVERSE=japan-trip` resolves to `<repoRoot>/evals/universes/japan-trip/`.
- **Path** — `OMNESIS_SYNTH_UNIVERSE=/some/other/dir` or `./local-universe` uses that path directly. Any value containing `/`, starting with `.`, or absolute is treated as a filesystem path.
- **Default** — unset → `default`.

The synth provider packages cache the active universe on first call, so the env var must be set _before_ any synth code runs (the test harness handles this in `synth-env.ts`; the demo scripts set it before spawning the gateway and collector).

## The manifest — `universe.json`

```jsonc
{
  "name": "example",
  "description": "One or two sentences describing this corpus.",
  "cast": "cast.json",
  "agentDemos": "agent-demos", // or null to disable the replay agent
  "devices": [
    { "id": "macbook", "name": "Jamies-MacBook-Pro-collector", "kind": "collector" },
    { "id": "iphone", "name": "Jamies-iPhone", "kind": "ios" },
  ],
  "sources": [
    { "descriptorId": "gmail", "accountIds": ["jamie.lopez@example.com"], "device": "macbook" },
    { "descriptorId": "notion-pages", "accountIds": ["user_jamie_lopez"], "device": "macbook" },
    { "descriptorId": "apple-health", "accountIds": ["ios-synth-jamie"], "device": "iphone" },
    // …
  ],
  // Optional: the multi-device mode each descriptor is exercised under.
  "multiDeviceModes": { "apple-health": "replicated" },
}
```

Fields:

- **`name`** — should match the directory name for in-tree universes.
- **`description`** — one or two sentences for tooling output.
- **`cast`** — path to the cast file, relative to the universe dir. Almost always `cast.json`.
- **`agentDemos`** — path to the agent-demos dir, relative to the universe dir. Set to `null` (or omit) for universes that only care about ingest/search.
- **`devices`** — the device roster: the synthetic devices this universe's documents come from. Each entry has a roster `id` (referenced by `sources[].device`), the `name` the device pairs under (unique per universe — device names are unique per gateway; a real collector pairs as `<hostname>-collector`, so name roster collectors the same way), and a `kind` — `collector`, or a kind that pushes sources itself (`ios`, `android`, `browser`); `cli`, `portal` and `agent` host nothing and are refused. Every seed source is attributed to one of these devices.
- **`sources`** — the seed list. Each entry has a `descriptorId` (must match a synth source descriptor like `gmail`, `apple-notes`, `whatsapp-messages`), one or more `accountIds`, and the roster `device` that hosts them. A type a phone or the browser extension pushes itself (`apple-health`, `core-location-visits`, `android-call-log`, `web`, … — the `DEVICE_HOSTED_SOURCE_TYPES` map in `@omnesis/types`) must sit on a device of a kind that hosts it; every other type sits on a `collector`. An entry may also list `members` — further roster devices that host the same sources as members joining the owner named by `device`; every member obeys the same kind rule, and only a descriptor with a non-exclusive `multiDeviceModes` entry admits members. The demo gateway iterates this list when seeding via `/admin/sources/add` (onto its single running collector — the demo has no synthetic phones, so phone-attributed sources are polled there by their synth twins, and members are not represented); the E2E harness uses each `discover()` and syncs every source as the roster device the manifest attributes it to — on every host, for a source with members.
- **`multiDeviceModes`** — optional; the multi-device mode (`handoff`, `replicated`, `partitioned`) each descriptor id is exercised under. Every harness device that hosts one of these descriptor ids announces its hosted override to the gateway, including phone and browser hosts, so the creating device can pin the source's mode the same way a real host does. A universe can therefore put a mode under test independently of whether the descriptor ships it. A descriptor without an entry is `exclusive`.

## Selecting a universe

**Demo gateway** — `--universe <name>`:

```bash
scripts/start-demo-gateway.sh start                          # default
scripts/start-demo-gateway.sh start --universe japan-trip    # named
scripts/start-demo-gateway.sh start --universe ./my-universe # path
```

Internally, the script exports `OMNESIS_SYNTH_UNIVERSE` and computes `OMNESIS_AGENT_FIXTURE=<universeDir>/agent-demos` (if the universe declares one).

**E2E test harness** — constructor options:

```ts
import { SyntheticE2EHarness } from "./synth-harness.js";

const harness = new SyntheticE2EHarness({
  gatewayMode: "stable",
  universe: "e2e-minimal",
});
await harness.start();
```

`gatewayMode` is required. Use `stable` for `OMNESIS_SYNTHETIC=0` and `OMNESIS_EXPERIMENTAL=0`, `experimental` for only the experimental gate, `synthetic` for synthetic-only test controls plus every surface guarded by `experimentalVisible()` while keeping `experimentalEnabled()`-only workers off, or `synthetic-experimental` when a test deliberately needs both flags. The harness writes both flags for every gateway boot, and its truth-table tests pin the exact tuple so ambient test-runner flags cannot silently change the product surface under test. At boot, `/health` can additionally verify whether gated surfaces are visible; it cannot distinguish the three visible modes. Synthetic mode reports `health.experimental: true` because production's `experimentalVisible()` treats it as sufficient to expose gated experimental surfaces.

Without a `universe` option, the harness inherits whatever `OMNESIS_SYNTH_UNIVERSE` is in the env (defaulted to `default` by `synth-env.ts`).

## Authoring a new universe

1. **Copy `evals/universes/default/`** to `evals/universes/<new-name>/` as a starting point — keep the directory shape, mutate the contents.
2. **Edit `cast.json`** — add/remove personas, edit cross-source aliases (`extra.notionUserId`, `extra.appleContactGuid`, …). The `self` field must point to a persona that exists in `people[]`.
3. **Replace the per-source fixtures** under `sources/<descriptorId>/`. The synth provider for each source expects the same schema as before — see `packages/providers-synth/<package>/src/fixtures.ts` for the entry type.
4. **Edit `universe.json`** — update `name`, `description`, the `devices` roster and the `sources` seed list (you can drop sources you don't care about); give every source the `device` that hosts it.
5. **Decide on `agentDemos`** — either author new scenarios under `agent-demos/`, copy and adapt the default ones, or set `agentDemos: null` and skip the replay agent for this universe.
6. **Validate** — `npx tsx scripts/validate-universes.mjs <new-name>` exits non-zero on errors (missing fixture files, broken cast, a source on a device that can't host it, dangling scenarios). Warnings are informational; errors block.
7. **Use it** — point the demo gateway or E2E harness at it.

## Which role a scenario answers for

A scenario's `.meta.json` may name the inference **role** it replays for:

```jsonc
{
  "role": "privacy-reviewer", // omitted ⇒ "agent"
  "triggers": ["the window is 09:00 to 11:00"],
}
```

Valid roles are `agent` (the chat surface and the `/answer` drafting pass),
`privacy-reviewer` and `background-agent`. The gateway builds one replay backend
per role over the same directory and each sees only its own scenarios, so one
universe can script both sides of a flow. The split is what makes routing
unambiguous: a privacy reviewer's first message is a JSON envelope quoting the
external question verbatim, so a shared pool would let the question's own trigger
match the envelope and replay the draft the reviewer was asked to review.

## Live tool calls in a cassette

A cassette's `agent.tool.start` normally sits next to a recorded
`agent.tool.result`; both replay verbatim and the tool never runs, which is what
a recorded demo wants — the corpus has moved on since the recording and a live
`search_many` would answer differently.

Omit the result and the replay backend runs the **real** tool with the recorded
arguments instead, emitting its actual result. Use this where the tool call _is_
the outcome rather than a step towards it: the privacy reviewer completes its
review by calling `submit_privacy_review`, so a replayed result would leave the
gateway with no review to act on.

## Driving privacy exchanges — `privacy-requests.json`

A privacy exchange starts outside Omnesis, so scripting one takes a request as
well as cassettes. `agent-demos/privacy-requests.json` lists the external calls
that set this universe's privacy cassettes going:

```jsonc
{
  "requests": [
    {
      "externalAgent": "Northwind Ops", // becomes the token name, i.e. the displayed caller
      "workflowName": "Delivery desk",
      "workflowPurpose": "Answer courier scheduling questions for open orders.",
      "question": "When is the Halden Press order due to arrive?",
    },
  ],
}
```

`scripts/synth-gateway.sh` seeds these after the sources: one `agent`-kind device
and one `answer`-scoped token per named external agent, then a `POST /answer` per
request with `approval: "never"`. Everything on the Privacy page therefore comes
out of the real drafting → review → release pipeline; nothing is written into the
database directly. Re-run just this step with `scripts/synth-gateway.sh
seed-privacy`. A universe that ships no `privacy-requests.json` skips it.

Workflow and conversation ids are deliberately absent — the gateway rejects ids
it has not issued, so it mints them.

The `default` universe uses this to reach all three answer-comparison states an
exchange can show: a release the reviewer allowed unchanged (`identical`), a
reduction that edits lines (`diff`), and a wholesale rewrite too unlike its draft
to describe as an edit (`no_diff`, reason `dissimilar`).

## Recording replay-agent scenarios

Replay-agent cassettes (`agent-demos/<name>.jsonl`) can be authored by hand, but the
fastest way to get a realistic one is to **record a real agent turn**:

```bash
scripts/record-replay-scenario.mjs --name my-scenario --prompt "What did Maya send me last week?" \
    [--universe default] [--triggers "maya,from maya"] [--after-ms 30] [--force]
```

What it does:

- Boots the synthetic harness with its **own** isolated gateway on a high port in a
  throwaway config dir — it never touches a live instance.
- Wires that gateway to the **configured** agent backend, read read-only from your config
  dir (`OMNESIS_RECORD_CONFIG_DIR` → `OMNESIS_CONFIG_DIR` → `~/.config/omnesis`),
  i.e. whatever `inference.assignments.agent` points at. If no agent is configured (unset,
  `null`, or `"replay"`), it **fails loud** — it records a real model stream and never
  silently substitutes a stub.
- Syncs every synthetic source so the agent has a corpus to ground on, drives the prompt,
  and captures the real `/agent/events` SSE stream.
- **Placeholder-izes only the ids it minted** (the session/message ids → `$SESSION` /
  `$MSG`, which the `ReplayBackend` substitutes back at replay time). Everything else that
  looks real — an email off a reserved domain, a phone, an IP, a credential shape, a long
  hex / UUID / base64 token — is **flagged and the recorder refuses to write the cassette**,
  naming the offending lines. This is a loud must-review-before-commit gate so a real
  secret or an un-mapped runtime id can never be silently recorded. Redact and re-run, or
  hand-edit, then commit.
- Writes `agent-demos/<name>.jsonl` (with a comment header recording the prompt + backend)
  plus a `<name>.meta.json` with the routing triggers.

After recording, run the validator (below) — the round-trip check confirms the cassette is
replayable, and `replay-scenarios.e2e.test.ts` will drive it end-to-end through the gateway.
Always read the recorded cassette before committing it.

## Threading live-minted ids: `capture`

A cassette whose tool calls run live (no recorded `agent.tool.result`) hits a problem a
chat cassette never does: the result is **real**, so the ids in it are not the ids the
recording saw. A cassette that created a loop and then appended to its ledger would address
a loop that never existed.

An entry may therefore declare `capture` — a map of name → dot path into that call's live
result — and later entries reference what was captured as `$CAP_<name>`:

```jsonl
{"afterMs":0,"event":{"type":"agent.tool.start","payload":{…,"tool":"open_loop_create","args":{…}}},"capture":{"loop1":"data.loop.id"}}
{"afterMs":0,"event":{"type":"agent.tool.start","payload":{…,"tool":"open_loop_ledger_append","args":{"id":"$CAP_loop1","note":"…"}}}}
```

The capture table is per turn, so replays never leak ids into each other. Names must match
`[A-Za-z0-9_]+`, and the substitution runs longest-name-first so `loop1` cannot eat a
reference to `loop10`.

Both ways this goes wrong are silent at replay time — an unresolved reference is handed to
a real tool as the literal `$CAP_…` — so the validator checks them: a reference with no
earlier capture, a reference that PRECEDES its capture (the table fills in emission order),
a capture on an event that is not a tool call, and a capture on a call whose recorded
result means it never runs live.

`scripts/record-brain-scenario.mjs` derives captures automatically when it converts a
cognition-run transcript into a cassette.

## The validator

`scripts/validate-universes.mjs` walks `evals/universes/*/` and checks each universe for:

- **Manifest** — parses against the `UniverseManifest` schema.
- **Cast** — `self` must reference a `people[]` entry; `people[]` must be non-empty.
- **Device roster** — roster ids and device names are unique, and each device's kind can host the source types attributed to it (a phone-pushed type on a phone of that platform, everything else on a collector). A source naming a device outside the roster fails to load at all. A device no source is attributed to is a warning.
- **Sources** — every `sources[].descriptorId` has a `sources/<id>/` directory with at least one `.json` file.
- **Agent demos** — each `.meta.json`'s `role`, when present, names a role a replay backend is actually built for; every `.jsonl` has a matched `.meta.json` sibling; each cassette **round-trips** (every event line parses + re-serialises stably into the `{ afterMs, event: { type: "agent.*", payload }, capture? }` shape the `ReplayBackend` loader consumes, so a recorded scenario is provably replayable, not silently malformed); **capture/reference integrity** holds (see below); and each `.meta.json`'s `placeholders.docExternalIds[]` is best-effort substring-matched against the source fixtures (warnings on misses, since some IDs are computed at sync time rather than baked into the JSON).

Run all in-tree universes, or one by name/path:

```bash
npm run validate-universes                       # all in-tree universes
npx tsx scripts/validate-universes.mjs default   # one by name
npx tsx scripts/validate-universes.mjs ./some/path
```

Exit code is 0 with only warnings, non-zero on any `error`-severity issue. `npm run validate-universes` also runs in CI (`.github/workflows/ci.yml`) before the test suites, so a structurally broken universe reddens the build.

## Implementation pointers

- Loader: `packages/providers-synth/_common/src/universe.ts` — exposes `loadActiveUniverse()`, `loadUniverse(nameOrPath)`, `loadSourceFixtureJson(...)`, `loadCastFromUniverse(...)`, `validateUniverse(...)`, and `UniverseError`.
- Cast: `packages/providers-synth/_common/src/cast.ts` — delegates to `loadCastFromUniverse(loadActiveUniverse())`.
- Synth providers: each `packages/providers-synth/<pkg>/src/fixtures.ts` calls `loadSourceFixtureJson(loadActiveUniverse(), "<descriptorId>", "<file>.json")` instead of static `readFileSync`.
- Demo scripts: `scripts/start-demo-gateway.sh` + `scripts/synth-gateway.sh` — accept `--universe <name>`, export `OMNESIS_SYNTH_UNIVERSE` to subprocesses, and seed via the manifest's `sources[]`.
- E2E harness: `packages/collector/src/e2e/synth-harness.ts` — requires an explicit `gatewayMode` in `SyntheticHarnessOptions`, accepts `universe?: string`, and accepts `extraInference?` to inject an arbitrary configured backend (the recorder uses it to wire the configured `agent` assignment). It pairs the universe's device roster into its gateway (one device row + token + `SyncEngine` per roster device — a collector pairs with the `syncLease` capability, as the real one does) and registers each seed source as the device the manifest attributes it to. The manifest's `multiDeviceModes` are declared on the definitions the engines run and announced by each synthetic host for the types it carries, so the creating host pins the source contract before a handoff, replicated, or partitioned source syncs. `getDevices()` / `deviceForSource(id)` / `devicesForSource(id)` expose the pairing (a source with members is synced by each of its hosts; `triggerSyncAndWait` waits for every host unless given one), `onStatusChange(listener)` observes every engine's status events (for a tick that must report nothing), and `pushDocument(s)` injects under the harness's own admin identity for tests that want an unattributed document.
- Recorder: `scripts/record-replay-scenario.mjs` (CLI shell) + `scripts/lib/replay-recorder.mjs` (pure placeholderization + flag-and-fail guard, reusing `scripts/pii-scan.mjs`'s detector). Tested by `scripts/record-replay-scenario.test.mjs`.
- Test-side env defaults: `packages/collector/src/e2e/synth-env.ts` — selects synthetic providers in the test process and sets `OMNESIS_SYNTH_UNIVERSE=default` for E2E tests that don't override; it does not choose the spawned gateway's feature mode.

## Current limitations

- **No procedural generation.** All fixtures are hand-authored JSON committed to the repo; there is no fixture generator.
- **No versioning / compat checking.** There is no `version` field and no schema-mismatch detection. Universes are read at face value.
- **No universe registry beyond the in-tree `evals/universes/` directory.** External universes work via path-mode but aren't discoverable as names.
