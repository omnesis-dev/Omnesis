Run the built-in agent on a Claude subscription through Claude Code. The new `claude-code/<model>` backend uses the operator's own installed and signed-in `claude` CLI (Claude Code 2.1.259 or later) on the gateway host; Omnesis never signs in to Claude or reads its credentials, and API-key variables are never passed to the CLI. It serves the same roles as Codex, among them the agent, background agent, privacy reviewer and image OCR, but not embeddings or transcription; a CLI older than the minimum is reported as needing `claude update`. Each turn is an isolated `claude -p` process in an empty Omnesis-owned directory with every built-in Claude Code tool removed; Omnesis loads none of the operator's settings files, so no settings-enabled plugins, hooks or MCP servers, switches off Claude Code's built-in plugins, and fails the turn if Claude Code offers any tool outside Omnesis or loads skills, sub-agents, slash commands or outside plugins, or runs a hook, a background task or a tool Omnesis did not call. It refuses to start Claude Code where the host's managed policy settings make it run commands of its own. Manage it with `omnesis claude-code status|refresh|setup-agent` or under Settings → Models → Backends, and `omnesis doctor` reports `models.claude-code`. An interactive gateway install with `claude` on the PATH and no agent model offers to set it up with Haiku.
