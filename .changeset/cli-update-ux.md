Clearer `omnesis update` output, and Docker updates that clean up after themselves. When the update takes its own backup, the plan now says so and names the backups folder, instead of telling you to back up first; that advice remains only for an update that takes no backup, such as one run with `--no-backup`. The install step now says what it did ("Pulled the 0.7.4 images", "Installed", "Built"), and "Updated to" appears once, as the last line, after the gateway serves the new release and everything else has restarted; with restarts left to you, the last line says what is installed and that the steps above finish the update. A Docker update pulls its images quietly, with Docker's own errors still shown when a pull fails, and pulls the updater image with the others. Once the gateway answers on the new release and the collector has restarted onto it, it removes the previous release's images of that install, about a gigabyte each, and never any other image; an image a container still uses is removed by the next update, and an image it cannot remove is a warning that names the command, never a failed update. The pre-update backup now says why it leaves out the search index: the gateway rebuilds it from the documents. In `omnesis sources add`, the account picker selects with the same keys as the source picker and shows the same hint. `omnesis devices list` sizes its columns to their contents, so a long name or hostname no longer pushes the rest of its row out of line. A CLI token that has never reported its version, such as the one the installer creates, no longer counts as an "unknown" device in `omnesis status` and `omnesis doctor`, and its STATE shows "—". A gateway with experimental mode off no longer lists the experimental Brain's wiki (`brain-knowledge`) or open-loop sources in `omnesis status`.
